# 单元测试会把 bug 固化

## edits

| 组件 | 改了什么 | 观察到的差异 | 判定 |
|---|---|---|---|
| `core/conn_url.rs`（单测） | 断言从剥掉斜杠改成保留斜杠 | 测试从「绿且错」变成「绿且对」 | helped |
| `scripts/acceptance.sh` | 断言改成用 python 按值取 JSON | 验收脚本不再因格式误报 | helped |

## lesson

- **cue**:一个测试断言写错了语义(不是写错了语法),而实现刚好符合这个错断言
- **lesson**:
  单测断言的是**实现的行为**,不是**需求的语义**。当单测和验收脚本
  冲突时,先怀疑单测 —— 尤其当单测是照着实现写的、而不是照着需求写的。
  判据:如果一条断言是在「实现写完之后照着结果补的」,它就没有验证力。
- **evidence**:上面两行 edits。冲突的现场:单测断言
  `sqlite:///tmp/a b/c.db` → `tmp/a b/c.db`,验收脚本用真绝对路径连,
  报 `unable to open database file`。
- **confidence**:high —— 同一个 bug 被两种验证方式同时暴露,机制清楚

## 附带的另一条

验收脚本第一版的两处断言也是错的:JSON 输出是 pretty-print 的,
值在单独一行,而我按紧凑格式写了子串断言(`'"n":3'`),于是**代码是对的、
断言是错的**,误报两处失败。

→ **验收断言要按值取,不要按子串猜。** JSON 用 python 解析后取路径,
不要 `grep` 一个拼出来的字符串。
