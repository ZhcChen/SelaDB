### 01-workbench-light

> SelaDB 主工作台(浅色主题):左侧对象树 + 右侧空白工作区,顶部标题栏与工具栏,底部状态栏。

**布局与信息密度 — 3/5**

主工作区采用垂直堆叠的大内边距卡片，整体信息密度严重偏向通用 Web SaaS，导致大部分工作区成为无意义留白；左侧树结构行距过宽，无法承载密集数据库对象。

- 主工作区‘快速开始’卡片内边距过大（约 16-20px），三张卡片加最近打开列表局促地挤在中上方，右侧大面积空间闲置
- 左侧对象树节点垂直高度过高（约 36px），缺乏原生树组件的紧凑感与缩进引导线，展开后能展示的表数量严重受限
- 底部状态栏仅有两端各几个字符，高度偏低且未划分固定网格分区（如编码、延迟、只读/读写状态区）

**对比度与类型可辨识 — 3/5**

浅色主题下大量次要文案与占位符对比度不足，最近打开项的色彩编码缺乏明确语义且与文本对比不够清晰。

- 顶栏及左栏搜索框中的占位符文字（‘筛选对象’、‘搜索对象或执行命令’）对比度低于 3:1，浅灰色过淡不易辨识
- 快捷卡片内的说明文字（如‘在当前连接上写 SQL’）灰度过高，在浅蓝/浅灰背景上辨识度差
- ‘最近打开’列表中的数据库引擎前缀使用青绿/深蓝色点，与右侧深色表名缺乏主次分层，且圆点语义不明

**专业观感 — 2/5**

视觉语言更像轻量级 Web 工具或模板后台，缺乏专业桌面数据库客户端（如 TablePlus、DBeaver）的沉稳感、高密度和严格的状态机控制。

- ‘快速开始’采用圆角大卡片与浅蓝图标容器，呈现明显的移动端/Web 引导页风格，脱离桌面 IDE 语境
- 在未选中任何连接或开启事务时，顶部的‘提交’与‘回滚’按钮处于高亮可点击视觉状态，不符合数据库工具严格的上下文逻辑
- 顶部工具栏按钮使用大圆角与双重线框，与标题栏融合生硬，像网页中的浮动 button 组而非紧凑工具条

**修改建议**

- 将主工作区‘快速开始’大卡片改为紧凑的纯文本/小图标列表或命令面板（高度压至 28-32px，圆角缩至 4px），消除松散的 Web 卡片感
- 将左侧连接树节点行高从约 36px 压缩至 24-26px，并增加标准的树状缩进虚线与 14px 紧凑图标
- 建立状态联动规则：未连接或未开启事务时，将顶栏‘提交’、‘回滚’按钮设为 disabled（降低不透明度至 40% 并禁用悬停态）
- 将所有输入框占位符及次要说明文字（description）颜色加深至至少 #64748b，满足 WCAG AA 级 4.5:1 对比度标准
- 重构‘最近打开’为双列紧凑表格视图（表名居左、所属连接及引擎以浅灰 tag 居右、时间居最右），统一字号为 12px

### 02-grid

> SelaDB 的数据网格:左侧对象树,右侧是 PostgreSQL 的 users 表,含虚拟滚动的数据行、粘性表头、类型着色、NULL 样式。

**布局与信息密度 — 3/5**

整体框架紧凑、分区明确，但在专业数据网格排版上存在数值对齐错误及表头空间浪费问题，信息存在重复展示。

- 数值列（id、balance）采用居左对齐，严重违背专业数据工具与财会排版规范，应严格靠右对齐以便按位数比对。
- 表头将字段名与数据类型硬拼在同一行（如 'balance numeric(12,2)'），过度挤占水平宽度，导致列名与类型无法清晰换行扫描。
- 行数信息在表格右上角（'600 / 1284 行'）与底部状态栏（'1,284 行 · 已加载 600 已选 1 行'）重复出现，造成界面噪音和信息割裂。
- 顶部搜索框采用大圆角药丸胶囊风格，与工具栏其他矩形/微圆角控件风格不协调，占用垂直空间过高。

**对比度与类型可辨识 — 3/5**

文本基础可读性尚可，但类型语法着色冲突严重，同色系无法区分，布尔值对比度失衡。

- 整型（id）与浮点金额（balance）共用完全相同的亮蓝色（#0066cc 档位），扫视时无法凭借颜色区分数值子类型。
- UUID 列采用浅青蓝，与数值列的深蓝同属冷蓝系，全表放眼望去冷色色块扎堆，失去类型着色的导视作用。
- 布尔值 false 采用了极淡的浅灰色，在纯白底色上对比度严重不足（低于 WCAG AA 4.5:1），容易被误看成空字符串或残影，而 true 的饱和度又过高。
- 表头类型注解（如 'varchar(255)', 'integer'）灰度过浅，难以快速识别类型定义。

**专业观感 — 3/5**

具备桌面 DB 工具的基础框架，但局部细节（数值左对齐、顶部大圆角搜索、纯 Web 风格 tab 栏）透露出通用 SaaS 模版的影子。

- 数值左对齐在 DBA/数据分析师眼中是极具业余感的 Web 默认行为，缺乏成熟桌面客户端（如 Navicat/DBeaver）的严谨度。
- 数据网格单行背景完全为纯白且无斑马纹/细微背景交替，连续阅读 20+ 行单调且容易横向串行。
- 右上角全局操作区（Auto、数据源下拉、搜索、窗格控制）与中间表标签栏（PG users）层级边界模糊，缺少桌面原生窗口的结构厚度。

**修改建议**

- 将所有数值类型（id、balance、数字统计等）的数据单元格与表头全部改为 text-align: right，并使用等宽数字字体（font-variant-numeric: tabular-nums）。
- 重构表头结构：将列名（加粗正文字体）与类型定义（10px 浅色大写或弱化括号注记）拆分为上下两行显示，避免横向挤占空间。
- 调整类型着色方案：将 UUID/哈希类降权为中性灰等宽文本，整型与浮点采用不同明度/色相（如整型用普鲁士蓝、浮点/金额用紫红或青褐），避免满屏高饱和纯蓝。
- 修复布尔值色彩：将 false 提升至 --fg-muted（暗灰，对比度 ≥ 4.5:1），将 true 的刺眼草绿调整为符合 WCAG 的森林绿/低饱和墨绿，或改用紧凑的只读复选框控件。
- 移除表格右上角的重复行数统计（'600 / 1284 行'），收敛到底部状态栏统一呈现，右上角仅保留紧凑的“数据 / 结构 / DDL”分段控制器与刷新按钮。

### 03-nosql

> SelaDB 的 Redis 键列表:左侧对象树展开到 db0 与类型分组,右侧是键值表格。

**布局与信息密度 — 3/5**

整体框架具备专业客户端结构，但主内容区信息密度偏低，垂直与水平空间浪费明显，表格与过滤栏布局不够紧凑。

- 顶部过滤输入框占满整行且高度偏大，左侧占位符文案与实际 Redis 场景不符，'清除'按钮孤立，造成大量纵向空间浪费
- 表格行高（约 32px）对于专业密集型查看偏高，单屏仅露出约 23 行，留白过多
- value 列占据剩余全部宽度但内容无格式化且被截断，缺少右侧独立详情预览抽屉/面板
- 左侧对象树计数胶囊（如 1,284 / 8,412）右侧对齐间距过大，且右侧边框与树文本之间留白松散
- 表头右侧存在空白占位列且无列宽自适应限制

**对比度与类型可辨识 — 3/5**

主要文字与背景对比度尚可，但类型标签全部使用低饱和度浅底彩色药丸，且表格内容未按数据结构做语法着色，辨识效率低。

- type 列（string/hash/list/set/zset）使用浅色带框胶囊，在白底下对比度弱，且 string（浅绿）与 set/zset（浅橙/浅粉）饱和度偏低，快速扫视不易区分
- value 列长文本（JSON、数组字符串）完全使用单一黑色正文展示，没有键名、字符串、数值的语法高亮，高密度浏览时极为费眼
- 行号（# 列）颜色偏淡且与 key 列的文字颜色阶梯不够明确
- 顶部标签页（PG/MYSQL/MONGO/REDIS）未选中态对比度过低，且关闭按钮 '×' 极浅，悬停或弱视环境下不易发现
- 底部状态栏文字与左下角连接信息对比度偏弱（淡灰字）

**专业观感 — 3/5**

界面带有明显的通用 Web/SaaS 管理后台质感（圆角胶囊、大号纯文本输入框），缺少原生 DB 客户端（如 TablePlus/Navicat）的精细紧凑度与专用交互。

- 过滤栏使用类似 Web 表单的大输入框，占位符为 SQL 表达式 'id > 100'，在 Redis 上下文中显得业余且不符合 MATCH 模式筛选逻辑
- 数据类型标签采用 Web UI 常见的 Rounded Badge 风格，增加了无意义的视觉噪点，不如纯等宽文本或微型彩色点标专业
- 工具栏中 '查询'、'提交'、'回滚' 属于 RDBMS 事务概念，当前停留在 Redis 标签页时未做上下文禁用或隐藏
- 缺少 Redis 必备的操作控件：如 TTL 快捷修改、重命名 Key、SCAN/KEYS 切换、刷新单键等专业动作按钮

**修改建议**

- 将表格行高压缩至 24–26px，并将数据字体统一设为 12px 紧凑等宽字体（如 JetBrains Mono / SF Mono），单屏展现行数提升 30% 以上
- 重构过滤工具栏：高度降至 26px，将占位符改为 Redis 专用的 'SCAN MATCH pattern* [COUNT 100]'，并集成刷新与类型过滤下拉菜单
- 取消 type 列的圆角 Badge 描边底色，改为纯等宽小写文本配合左侧 4px 语义色圆点或微型色块标签（string 纯蓝、hash 橙色、list 紫色、set 绿、zset 品红）
- 对 value 列根据首字符自动应用轻量语法高亮（JSON 键名与标量着色），并在右侧提供可折叠的 Key 详情与格式化查看抽屉（View as JSON/Raw/Hex）
- 根据当前活动的数据库连接类型（Redis）动态切换顶部工具栏操作，隐藏无关的事务提交/回滚按钮，替换为 Redis CLI 终端入口与 Flush/Reload 操作

### 04-workbench-dark

> SelaDB 主工作台(深色主题):左侧对象树 + 右侧空白工作区。

**布局与信息密度 — 3/5**

整体骨架清晰，但工作区空状态采用了典型的 Web SaaS 大卡片堆叠，信息密度过低，缺乏专业客户端的紧凑与高效感。

- 右侧‘快速开始’采用大内边距的块状卡片与松散垂直排列，屏幕空间利用率极低，与专业 DB 客户端的多标签/紧凑网格模式不符
- 左侧对象树行高偏大（约 34-36px），单屏可展现节点数偏少，未体现专业工具的高密度层级树特征
- 顶部工具栏功能划分松散，在‘未选择连接’状态下‘提交’与‘回滚’按钮直接暴露且无明确的禁用/灰阶状态区分
- ‘最近打开’列表采用单列松散文本，缺乏数据库引擎类型、更新时间、归属库等元数据列对齐展示

**对比度与类型可辨识 — 3/5**

深色背景与关键彩色标识对比鲜明，但次级说明文字与占位符对比度偏低，彩色指示条过亮造成视觉干扰。

- 卡片副标题（如'在当前连接上写 SQL'、'按表名、字段名查找对象'）与背景对比度不足 3:1，低光或反光屏幕下不易辨认
- 左侧连接项左侧的彩色指示细条和插头图标饱和度过高（荧光青、高亮红），夺取过多视觉焦点，反衬出连接名称文字偏暗
- 顶部全局搜索框的占位符文字以及快捷键徽标（⌘K）暗度过高，可读性较差
- 底部状态栏背景与主工作区底色几乎无明度阶梯分割，仅靠一条微弱细线，边界感薄弱

**专业观感 — 2/5**

界面带有浓厚的通用 Web SaaS / 管理后台模板感，缺乏沉稳、密集、功能导向的桌面级专业数据库软件质感。

- 中间区域的快速开始卡片具有明显的 Web 页面痕迹，专业工具（如 TablePlus、DataGrip）通常采用快捷键引导、多标签工作台或结构化仪表盘
- 左侧树节点的连接状态与类型标识（细竖条 + 彩色插头）显得随意，缺乏商业工具中常见的小尺寸严谨图标（如标准的 DB 类型徽标与连通状态角标）
- 顶部操作栏中的‘查询/提交/回滚’样式为常规 Web 按钮组，缺乏桌面端工具栏的紧凑 Icon-Button 规范

**修改建议**

- 重构右侧空白页：废弃 Web 式大卡片，收缩为紧凑的快捷指引面板或分栏网格，加入结构化的最近打开列表（包含引擎图标、对象类型、所属连接、最后访问时间等元数据表格）
- 压缩左侧对象树行高至 24–26px，使用标准的 16x16 引擎 Logo（PG/MySQL/Mongo/Redis）替代彩色竖条和单调插头图标
- 建立连接状态约束：未激活任何连接时，将顶部‘提交’、‘回滚’按钮置为 disabled 浅灰状态，或收归至事务专用的下拉分段控件中
- 提升辅助文字对比度：将卡片说明、搜索框占位符及状态栏文本的明度从当前约 #555c6d 提升至 #8c96a8，确保符合 WCAG AA 标准
- 标准化顶部工具栏尺寸与圆角：将工具栏高度压缩至 36px 左右，搜索框与按钮圆角统一调整为 4px，减少通用 Web 模板的圆润浮夸感

### 05-spec

> SelaDB 的设计规范页:展示设计 token 色板(主题色、数据类型色板、引擎品牌色)与组件清单表格。

**布局与信息密度 — 3/5**

典型的 Web SaaS 规范展示排版，色块卡片留白过大，网格分布不均，未能在真实表格上下文中体现专业工具的高密度特性。

- 数据类型色板排布失衡：第一行 6 项、第二行 3 项，右侧留出大片无意义的空白区域，未按逻辑分类（数值类、文本类、复杂对象）分组对齐。
- 组件清单密度偏低：表格行高接近 44-48px，留白松散，接近 Notion 等通用文档风格，未体现 TablePlus/DBeaver 类工具 24-28px 的高密度排版特征。
- 缺少上下文参照：纯卡片罗列无法直观展示其在 DataGrid 紧凑单元格或 TreeView 节点中的实际排布表现。

**对比度与类型可辨识 — 2/5**

核心数据类型在色相与明度上存在严重混淆，且大面积色块未考虑实际作为文字/单元格背景渲染时的对比度问题。

- --type-int（整数）与 --type-float（浮点/金额）使用几乎同色相的蓝色，在密集表格中扫视时完全无法快速肉眼区分。
- --type-string（字符串）使用极深的墨黑灰，与 --fg-default（正文前景）几乎没有对比反差，失去了类型着色的提示意义。
- 未定义在选中态下的对比方案：当单元格处于 --bg-selected（浅蓝背景）时，蓝色的 --type-int 和 --type-float 会立即发生对比度衰减甚至不可读。

**专业观感 — 3/5**

视觉风格偏向通用前端文档/设计规范后台，色彩管理过于花哨（彩虹色数据网格），偏离了严肃开发者工具追求低视觉噪音的标准。

- 数据类型定义了多达 9 种高饱和度对比色，在数千行密集网格中直接应用会导致极度严重的'彩虹糖效应'与视觉疲劳。
- 组件清单中的优先级采用了大圆角胶囊状描边标签（P0），带有过重的轻量 Web 应用痕迹，缺乏原生桌面工具的克制与硬朗感。

**修改建议**

- 将 --type-float（浮点）与 --type-int（整数）拉开色相，浮点数建议改为青蓝（Cyan/Teal #0891b2）或改用字重/后缀区分，避免双重纯蓝混淆。
- 为数据类型建立前景色/徽标底色成对 Token（如 --type-*-fg 与 --type-*-subtle-bg），确保文字在白底、深色底及 --bg-selected 浅蓝选中态下均满足 WCAG AA 4.5:1 对比度要求。
- 降低数据网格默认彩虹色噪点：将 String 与常规数值弱化，重点仅保留 NULL（斜体浅灰）、Boolean（高辨识对比）、Blob/Binary 及 JSON 的特征高亮。
- 压缩组件清单表格行高至 28-32px，将 P0/P2 胶囊圆角改为 2-4px 微圆角或纯文本等宽标记，靠拢 TablePlus/DBeaver 的紧凑工程观感。

### 06-entry

> SelaDB 设计源的总入口页,两张卡片分别通向规范页与产品预览。

**布局与信息密度 — 3/5**

作为设计源总入口，全屏有效内容占用率不足 20%，留白过度导致信息极其稀疏，两张卡片缺乏明确的点击引导与层级区分。

- 整体视口利用率极低，主体内容局限在视口中心极小区域，更接近通用 Web Landing 页而非桌面级专业工具的入口与规范控制台
- 两张卡片（产品预览与设计规范）缺乏直观的交互线索（缺少进入箭头、按钮形态或明确的悬浮区域指示），底部的 `#/design` 与 `#/spec` 像静态注记而非可点击路由
- 下方引擎状态列表与底部说明文字的垂直间距松散，缺乏结构化的分组容器，悬浮在空白背景上显得零散

**对比度与类型可辨识 — 2/5**
