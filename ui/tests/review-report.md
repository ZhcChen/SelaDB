### 01-workbench-light

> SelaDB 主工作台(浅色主题):左侧对象树 + 右侧空白工作区,顶部标题栏与工具栏,底部状态栏。

**布局与信息密度 — 2/5**

整体布局过于松散空旷，严重偏向通用 Web 应用而非高密度桌面开发工具；右侧空白态有效信息承载率极低，垂直与水平留白失衡。

- 右侧工作区居中卡片（新建查询、新建连接、全局搜索）占地过大但仅容纳3个入口，横向拉开后大量白屏被浪费，缺乏专业客户端欢迎页的紧凑度（如缺少快捷键列表、系统状态、常用连接卡片等）
- 左侧导航栏（对象树）条目行高过大，单行高度约 36-40px，在没有大量连接时显得空洞，若连接和表展开后同一屏能显示的对象数量过少
- 右侧工作区顶部缺少原生标签页栏（Tab Bar）占位，仅右上角有孤立的“+”按钮，缺乏多标签多任务上下文切换的视觉骨架
- 底部状态栏高度偏小且两端信息极其稀疏，仅有两端极简的圆点和“就绪”，未有效利用空间承载编码、延迟、内存占用等信息

**对比度与类型可辨识 — 3/5**

浅色主题下大体可读，但弱化文字（次要文字、占位符、快捷键标注）对比度偏低，且缺乏专业工具关键的暗色边框与视窗分区边界。

### 02-grid

### 05-spec

> SelaDB 的设计规范页:展示设计 token 色板(主题色、数据类型色板、引擎品牌色)与组件清单表格。

**布局与信息密度 — 3/5**

排版工整但偏向通用 Web/SaaS 展示页，卡片尺寸偏大且留白过多，缺乏专业桌面工具紧凑的设计规范信息密度。

- 色块区域与下方文本区域 1:1 分割，导致变量名（如 --engine-postgresql）在窄卡片下容易拥挤或贴边。
- 页面整体采用居中固定宽度的大边距网页布局，未体现桌面端多列、紧凑的面板化布局结构。

**对比度与类型可辨识 — 2/5**

数据类型着色存在严重撞色与识别混淆问题，且 Token 变量名的正文对比度未达无障碍标准。

- --type-int（亮蓝）与 --type-float（深蓝）色相极度接近，在数据网格小字号下几乎无法快速区分数值子类型。
- --type-string 使用近黑色（深青黑），在亮色网格中与普通文本 --fg-default 无法区分；--type-uuid（蓝灰）与 --type-null（纯灰）色相和明度过于接近。
- 引擎品牌色中 PostgreSQL、MySQL、SQLite 三者全为深浅不同的蓝/青色系，在小尺寸状态指示灯或标签中辨识度极差。
- 卡片内下方的 CSS Token 变量名（如 --bg-canvas、--type-int）字色过淡（浅灰），在浅灰底色上对比度低于 WCAG AA 4.5:1 阈值。

**专业观感 — 3/5**

视觉风格偏向 Tailwind/Vercel 风格的 Web 演示站，数据类型的色彩映射逻辑脱离主流代码/SQL 编辑器直觉。

- 大圆角（约 8px-10px）卡片与轻量柔和阴影具有较重的 Web 表单/SaaS 质感，缺乏 DataGrip、TablePlus 风格的克制与严谨。
- 数据类型配色违背开发者直觉：开发者习惯将 String 映射为绿/橙红、数值统一归类、NULL 用低饱和斜体，当前色板把 String 设为近黑而将布尔设为纯绿，在密集网格中极易产生视觉杂乱。

**修改建议**

- 重构数据类型色相逻辑：数值类（Int/Float）合并为统一基色（如天蓝），将 --type-string 改为琥珀色/橙黄色系（代码高亮通用直觉），与普通正文拉开绝对差距。
- 拉开 NULL 与 UUID 的区分度：--type-null 强制降权为浅灰并配合斜体/虚线框，--type-uuid 改为专属的青绿或冷灰紫，避免与 NULL 撞色。
- 引擎品牌色增加特征色或强制配合官方 Monochrome 图标：SQLite 改用经典的深羽毛蓝配灰，MySQL 与 PostgreSQL 必须在明度和饱和度上做明显阶梯分层。
- 提高变量名文字对比度：将卡片底部 --type-* 与 --bg-* 的字色从目前的浅灰色加深至 --fg-muted（至少 #4B5563 / 对比度 ≥ 4.5:1）。
- 缩减色卡尺寸并提高信息密度：将卡片高度从 ~110px 压缩至 56–64px，圆角收敛至 4px，采用左侧 16px 色块条 + 右侧紧凑文字排版，更贴合桌面端紧凑规范。
