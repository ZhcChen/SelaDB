### 01-workbench-light

> SelaDB 主工作台(浅色主题):左侧对象树 + 右侧空白工作区,顶部标题栏与工具栏,底部状态栏。

**布局与信息密度 — 3/5**

结构清晰但空间利用率偏低，整体控件间距与行高偏大，呈现明显的 Web 后台而非高密度桌面开发工具特征。

- 左侧对象树单行高度过大（约 32-36px），展开库、模式、表层级后同屏可视节点数过少，缺乏紧凑感
- 左侧顶部的'筛选对象'输入框垂直高度与内外边距过大，占用了过多纵向树状目录空间
- 顶部工具栏高度偏厚，按钮之间与右侧搜索框占据空间过散，未做到桌面端典型的紧凑型单行 Titlebar/Toolbar 融合
- 右侧工作区在无打开对象时仅居中显示两行弱文字，缺乏 Tab 栏占位和常用操作引导（如新建查询、快捷键索引）

**对比度与类型可辨识 — 3/5**

主次文本灰度梯度不足，部分辅助图标与空状态说明文字对比度偏弱，长时间注视容易疲劳。

- 空状态副文本（'在左侧对象树里选择一个表...'）与背景色对比度不足，浅灰文本在冷灰底色上识别度偏低
- 左侧树展开折叠箭头（>）颜色过淡，不易看清父子节点层级展开状态
- 顶部命令搜索框（'搜索对象或执行命令 ⌘K'）的文字及边框过淡，容易被忽略
- 底部状态栏文字与灰色连接状态指示点在浅底色下对比度较弱，难以一眼确认当前连接状态

**专业观感 — 2/5**

视觉语言强依赖 Web 表单组件（大圆角、网页型输入框、居中空提示），缺乏 TablePlus/DataGrip 这类工具的原生感与工业感。

- 顶部'查询'、'提交'、'回滚'按钮外描边与大圆角带有明显的通用 Web SaaS 模板感，不像 IDE 工具栏控件
- 连接树仅使用通用的插头图标（🔌）和纯色彩条，未采用各数据库官方引擎 Logo（Postgres 象、MySQL 海豚、Redis 等），专业辨识度不足
- 右侧大面积空工作区使用整块冷灰蓝着色，与白色侧边栏割裂感明显，没有工作台面板（Panels）的专业布局感
- 空状态缺乏针对数据库工程师的实用设计（如最近打开的表、常用连接快捷方式、新建 SQL 快捷键提示）

**修改建议**

- 将左侧树节点行高从当前约 34px 压缩至 24-26px，并把各数据库类型图标换成对应引擎的标准品牌矢量图标
- 紧凑化左侧'筛选对象'栏：高度压缩到 26px 并与顶部分割线对齐，减少侧边栏无效垂向占用
- 收窄顶部工具栏高度至 32-36px，去掉'查询/提交/回滚'的卡片式描边与阴影，改为紧凑的平铺图标+文字工具栏按钮
- 在右侧空工作区预置常驻 Tab 标签栏骨架，并在主区域增加快捷入口卡片（如：新建查询 ⌘T、最近查询、导入连接）

- 重设 '--type-string'：不要使用黑灰色，改为暖绿、浅橙红或暗金红（如 #9254DE 或 #D46B08），并与系统正文文本色 '--fg-default' 明确剥离

### 14-value-editor

> SelaDB 的 Redis 键值编辑器:右侧抽屉里是元信息与按类型渲染的值编辑区。

**布局与信息密度 — 4/5**

- 右下角的 Toast 浮层（'已删除「orders」(mock)'）直接遮挡在状态栏与表格边缘，破坏了底栏的网格规整度。

**对比度与类型可辨识 — 3/5**

基本文字可读，但表头次级信息过暗，且复杂数据缺乏语法高亮与状态颜色语义区分。

- 左上角工具栏常驻并高亮了 '提交' / '回滚' 事务按钮，这在浏览 Redis db0 时属于无意义的关系型事务概念泄露。

- 将 TTL 列的 -1 改为暗灰色显示或替换为 '永不过期' / '∞'，带 TTL 的正整数赋予独立标识，便于一眼识别缓存过期策略。
- 将顶部的 'Redis db0 数据库 127.0.0.1:6379' 与下方的过滤输入框合并为一行工具栏，为数据列表节省 28px–32px 垂直空间。
- 为 value 列引入轻量 JSON 语法着色（键名淡蓝、字符串淡绿、数字橙黄），并在行末或点击时提供快速呼出右侧抽屉查看格式化 JSON 的快捷入口。
- 在当前处于 Redis 等非事务型/非关系型连接时，禁用或隐藏顶部工具栏中的 '提交' 与 '回滚' 按钮。
