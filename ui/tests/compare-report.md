# 改动前后成对比较

> 用 `node tests/review.mjs --compare` 生成。绝对打分有 ±1 分的抖动,
> 成对比较问的是「哪个更好」,相对判断稳定得多。

## 01-workbench-light —— 改后更好

改动后在空白工作区补齐了“快速开始”卡片与“最近打开”列表，大幅改善了原先大面积空置与弱引导的问题，操作入口更加直观明确；改动前信息量过于单薄且空间浪费严重。

**新引入的问题**:欢迎区内容整体偏左上方悬空，在宽屏下右侧仍显突兀且不平衡；顶部工具栏按钮被强行压缩进标题栏，导致顶栏元素拥挤、层级不够舒展。

## 02-grid —— 改后更好

改动后优化了顶部与筛选区域的布局结构，大幅节省了垂直空间并提升了数据网格屏效；表头将列名与数据类型分双行层级呈现，且修复了改动前 UUID 列渲染重叠失真的问题。改动前整体工具栏偏占空间，信息展示效率较低。

**新引入的问题**:筛选输入框被压缩至与表信息同行，长过滤条件的展示空间受限；列头的数据类型字体较小且对比度偏低，在窄列宽下容易被截断。

## 03-nosql —— 改后更好

好在改动后针对 Redis 特性进行了深度适配，类型列采用了彩色标签显著提升了视觉扫描效率，永久 TTL 显示为更直观的符号“∞”，且表头去除了不贴切的 SQL 类型标注；差在改动前呈现更像通用关系型数据表，类型纯文本混杂且“-1”的 TTL 表达较为生硬。

**新引入的问题**:顶部全局工具栏大幅精简并收起了“新建连接”、“事务提交/回滚”等高频动作按钮，操作直达性有所减弱。

## 04-workbench-dark —— 改后更好

好在改动后在空白工作区补充了“快速开始”快捷卡片与“最近打开”列表，有效利用了大面积黑屏空间并强化了引导性；差在改动前只有一行微弱的居中提示文本，视觉空洞且信息密度极低。

**新引入的问题**:快速开始内容块整体偏向主工作区左上方，导致右侧与下方留白分布不够均衡；左侧对象树选中态的双色指示条与彩色圆点略显视觉繁琐。

## 05-spec —— 改前更好

改动前色板网格与表格自适应撑满内容区，整体版面饱满、左右边距对称整齐；改动后元素宽度被强制收紧且左倾，导致卡片右侧留出大片未利用的空白，视觉重心严重失衡。

**新引入的问题**:色块与表格未能自适应容器宽度或整体居中，导致右侧出现大面积突兀的留白，破坏了规范页面的对称感与工整度。

## 06-entry —— 改后更好

改动后在卡片标题右侧补充了跳转箭头，明确了卡片作为入口的可点击属性；下方新增了支持数据库引擎的彩色标签状态栏，丰富了页面关键产品信息且提升了视觉层次。

**新引入的问题**:新增的支持数据库列表字号偏小、颜色偏杂，且与底部免责说明的垂直间距略显局促，稍有视觉拥挤感。

## 07-query —— 改后更好

好在查询结果网格的列字段与上方 SQL 查询（id、name、status、orders）准确对应，上下文信息表达真实一致；差在少数列场景下未合理收拢列宽，导致表格横向过散、右侧留白空旷。

**新引入的问题**:结果表格未对列宽做自适应或最大宽度约束，且 SQL 编辑器字体渲染变细，代码的可读性和紧凑感有所减弱。

## 08-query-error —— 改后更好

改动后在编辑器中为出错的表名增加了红色波浪线精确定位，且底部结果区补充了带有快捷键提示的纠错引导，信息传达更直观明确。

**新引入的问题**:顶部全局工具栏去除了醒目的‘新建连接’主操作按钮，导致顶栏视觉重心失衡且显得较为松散。

## 09-palette —— 改后更好

改动后底部补充了标准的键盘导航快捷键提示（↑↓/↵/esc），组件完整度与交互指引更清晰；改动前缺少操作提示，底栏留白生硬。

**新引入的问题**:弹窗整体宽度被明显收窄，导致右侧连接与层级路径（如 PostgreSQL · postgres / views）的横向展示空间较为局促。

## 10-document-tree —— 改前更好

改动前具有清晰的树形层级连接线，键值间距紧凑合理，文档卡片视觉边界明确；改动后移除了层级引导线，且键与值横向间距过大，导致视线跨度长、阅读对应吃力。

**新引入的问题**:改动后键值分列过于分散产生视觉割裂，丢失了树形缩进辅助线使得嵌套结构不易辨识，卡片头部的操作文字也被弱化为图标，降低了直观性。

## 11-structure —— 改前更好

改动前主键有独立的“键”列展示且表头结构边界清晰，改动后将 PK 标签强行塞进列名中破坏了文字对齐与阅读节奏。

**新引入的问题**:表结构视图中错误地混入了数据查询专用的“过滤条件”栏，且删去键属性独立列后不利于后续组合键或复合约束的清晰呈现。

## 12-ddl —— 改后更好

好在 DDL 预览区增加了标准代码行号，提升了长 SQL 语句及约束条件的阅读与定位体验；差在改动前缺少行号，更像纯文本展示而非专业代码预览。

**新引入的问题**:顶部栏混入了属于数据浏览界面的“过滤条件”输入框与清除按钮，在只读的 DDL 预览上下文中显得多余且产生语义混乱。

## 13-context-menu —— 改前更好

改动前数据网格表头层次清晰，列名与类型标签（如 PK 胶囊）排版规整，整体界面呼吸感更强；改动后把工具栏硬塞入顶栏显得拥挤杂乱，且数据表格表头文字被严重压缩变形。

**新引入的问题**:数据网格表头信息严重错位与截断，字段类型和约束标签缩成一团无法辨认，表格可读性发生严重退化。

## 14-value-editor —— 改后更好

好在 Redis 数据类型采用了色彩鲜明的标签化呈现，辨识度极高，TTL 永久过期用 '∞' 替代 '-1' 更符合直觉，且表头去掉了冗余的 SQL 伪类型标注；差在改动前纯文本表格信息扁平、类型区分度低。

**新引入的问题**:表格列宽未自适应撑满视口，导致右侧出现大片无效空白，且 value 列内容被过早截断。

## 15-connect —— 改后更好

改动后在参数表单页右下角新增了“测试连接”操作，符合数据库连接配置的交互直觉，无需跳转到后续步骤即可即时验证配置；改动前缺少就地测试入口，验证路径较长。

**新引入的问题**:顶部步骤条第3步仍命名为“测试与保存”，导致第2步的“测试连接”与第3步的语义产生重叠；且新增按钮样式较暗暗沉、与“下一步”主按钮的视觉节奏略显局促。
