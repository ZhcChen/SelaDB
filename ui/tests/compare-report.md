# 改动前后成对比较

> 用 `node tests/review.mjs --compare` 生成。绝对打分有 ±1 分的抖动,
> 成对比较问的是「哪个更好」,相对判断稳定得多。

## 01-workbench-light —— 改后更好

改动后将顶部双层栏整合为单行，显著节省了垂直空间；空白区引入了“快速开始”快捷入口与“最近打开”列表，大幅提升了首屏的信息利用率与引导性，相比改动前单薄的居中文字更实用现代。

**新引入的问题**:原顶部高亮显眼的“新建连接”主按钮及“提交/回滚”等快捷事务操作被移除或折叠；右侧欢迎内容整体偏左上方聚集，导致右侧大半区域留白较多、视觉重心略显失衡。

## 03-nosql —— 改后更好

改动后数据类型采用了直观的彩色标签展示，极大提升了视觉扫描效率；TTL 将无过期的 -1 替换为无穷大符号“∞”，且表头去除了多余的 SQL 类型声明，更贴合 Redis 语义。

**新引入的问题**:搜索占位符提示“key like cache:*”依然残留了 SQL 语法习惯，未完全转为 Redis 习惯的 glob/match 匹配表达。

## 04-workbench-dark —— 改后更好

好在改动后消除了空洞乏味的空白态，通过‘快速开始’卡片和‘最近打开’记录提供了高效的引导与历史追溯；差在改动前中央仅有一句弱引导文案，大面积空间被完全浪费。

**新引入的问题**:右侧内容整体偏向左上方，右下区域仍留有较多不平衡的留白；顶部导航栏调整后右侧控件排布略显拥挤，视觉重心稍有失衡。

## 05-spec —— 改后更好

改动后将底部的组件清单表格宽度收拢，与上方色板区域的版心边缘严格对齐，解决了改动前表格向右过度延展导致的视觉失衡问题，整体版面规整统一。

**新引入的问题**:无明显退化。

## 07-query —— 改前更好

改动前顶部工具栏与标签页分层清晰、各功能区比例匀称，数据网格的表头字段与类型排版规整易读；改动后强行将工具按钮与标签页合并，导致顶栏大面积空置而局部拥挤，整体视觉重心失衡。

**新引入的问题**:左侧导航树宽度被压缩，导致右侧的记录数计数（如 1,284、5,321）紧贴边缘甚至被截断遮挡；同时结果网格表头的列名与类型换行居中，视觉对齐凌乱。

## 08-query-error —— 改后更好

改动后在空白结果区提供了明确的操作指引（提示快捷键重新执行），避免与上方红色报错条内容机械重复；编辑器内的红色波浪线和报错条视觉层级更清晰收敛。

**新引入的问题**:顶栏工具栏被过度紧凑化，关键动作（如新建连接）被弱化或收折，右上角执行环境与控制项排布显得较为拥挤。

## 09-palette —— 改后更好

改动后弹窗位置更趋于视口居中，视觉重心更舒适；底部补充了键盘导航快捷键提示（↑↓、↵、esc），提升了命令面板的可用性与完整感。

**新引入的问题**:底部快捷键提示栏字号偏小且颜色过淡，可读性较低；同时列表下方到快捷键栏之间的留白略显空旷不匀称。

## 10-document-tree —— 改后更好

改动后去除了过重且刺眼的蓝色卡片标题栏，整体设计更轻量现代，让视线能更聚焦于 BSON 数据本身；但改动后文档头部的视觉对比度明显降低，在连续浏览多个文档时不如改动前容易快速界定单个文档边界。

**新引入的问题**:卡片头部原有的“复制 JSON”与“展开全部”等高频文本操作被精简为隐晦的小图标，降低了操作的直观性与可发现性。

## 11-structure —— 改后更好

好在将“键（PK）”列前置到列名左侧，免去了视线横跨整屏确认主键的成本，且顶部标签整合提升了垂直空间利用率；差在标签将数据/DDL与列/索引并列打平，层级逻辑不如改动前清晰。

**新引入的问题**:表格文字字号与粗细变弱导致可读性下降；“键”列夹在序号与列名间导致非键行出现视觉断层；视图切换（数据/DDL）与元数据分类（列/索引）层级混淆。

## 12-ddl —— 改后更好

改动后为 SQL 代码区增加了行号显示，极大提升了 DDL 的阅读与定位体验；子标签栏整合了带数量标记的表元数据维度（数据、列、索引、约束等），结构更系统专业。改动前缺少行号且表结构切换维度较为简陋。

**新引入的问题**:无明显倒退，但两层子标题栏（表级信息栏与 DDL 预览标题栏）连续堆叠略微占用了垂直编辑空间。

## 13-context-menu —— 改前更好

改动前表格列宽分布均匀紧凑，单行表头展示字段与类型更为精致高效，顶栏操作分区清晰；改动后虽然增加了带数量标记的元数据 Tab，但表头折行且列宽自适应失衡，导致右侧出现大面积无效留白。

**新引入的问题**:顶栏操作按钮布局被打散（提交/回滚位置突兀），表格列间距过大导致部分数据列（如 discount_amount）被挤出当前可视区域。

## 14-value-editor —— 改后更好

改动后为数据类型引入了高辨识度的彩色标签（Badge），极大提升了扫读与识别效率；TTL 永不过期用更符合直觉的 '∞' 替代了 '-1'，语义传达更清晰直观。

**新引入的问题**:TTL 列中数字与特殊符号 '∞' 混用且字宽不一致，导致该列视觉对齐略显不整齐；色彩标签较为密集时可能略微分散对键名的注意力。

## 15-connect —— 改后更好

改动后在底部操作区补充了“测试连接”操作，让用户在填写完配置后能就地验证连通性，信息动线更完整；改动前缺少即时测试入口，操作指引不够闭环。

**新引入的问题**:“测试连接”按钮默认带有勾选图标（✓），在未触发测试前容易被误读为“已测试成功”的状态提示而非操作按钮，且与第三步“测试与保存”的职责边界略显重叠。
