# 改动前后成对比较

> 用 `node tests/review.mjs --compare` 生成。绝对打分有 ±1 分的抖动,
> 成对比较问的是「哪个更好」,相对判断稳定得多。

## 01-workbench-light —— 改后更好

改动后侧边栏树节点（PostgreSQL/MySQL等）增加了左侧内边距，三角箭头不再紧贴左边缘，视觉呼吸感更好；顶部工具栏将 Auto 选择器与主搜索框解耦拉开间距，信息分区更加清晰独立。

**新引入的问题**:无明显视觉回归，侧边栏宽度与工具栏间距调整后各元素排版保持对齐工整。

## 02-grid —— 改后更好

改动后在视觉节奏和间距呼吸感上明显更好：1. 掩码显示顶栏右侧与中间存在明显位置调整，右上 2 倍放大图可见改动前全局搜索框与左侧连接选择器（露出的“— 本地”）挤在一起，改动后移除了紧挨堆叠，各功能区分布更均衡；2. 掩码显示左侧对象树存在整体垂直位移，放大图可见树节点与搜索框下方增加了适度内边距与行高，使层级折叠展开与选中的 users 节点更舒展易读；3. 右侧数据表格行高与边距微调后，高密度的数据库列（UUID、email）逐行扫读体验更佳。

**新引入的问题**:无明显退化，原有信息密度、粘性表头及底部状态栏信息均完整保留且排版更规整。

## 03-nosql —— 改后更好

改动后调宽了左侧导航树侧边栏的默认宽度，使对象树节点的数字徽标（如 1,284、5,321）不再紧贴分割线，呼吸感和层级展示更舒展；右侧 Redis 键匹配搜索框在输入筛选条件后增加了直观的“清除”按钮，状态指示与重置操作更明确。

**新引入的问题**:无明显视觉退化；侧边栏加宽后右侧表格整体微调后移，各数据列排版与对齐依然规范工整。

## 04-workbench-dark —— 改后更好

改动后适当加宽了左侧对象树侧边栏（掩码显示侧栏整条右边界线向右移），使「筛选对象」搜索框及下方的数据库连接列表空间更充裕；同时顶栏右上角移除了原本搜索框左侧的「Auto ▾」控件（掩码右上明显变动），使顶栏搜索框与快捷操作布局更加简洁整齐。

**新引入的问题**:无明显新问题，整体对齐和层级保持规范。
