# 改动前后成对比较

> 用 `node tests/review.mjs --compare` 生成。绝对打分有 ±1 分的抖动,
> 成对比较问的是「哪个更好」,相对判断稳定得多。

## 01-workbench-light —— 改前更好

改动前顶部栏的「刷新」与「查询」按钮尺寸精细，与品牌名之间有竖线分隔，整体工具栏视觉比例协调；改动后去除了品牌名右侧的分隔线，且「刷新」「查询」图标与文字被异常放大，破坏了顶部栏的精致感与对齐秩序。

**新引入的问题**:顶部工具栏左侧的操作按钮字号与图标尺寸偏大，与右侧搜索框及控件的字号比例失调，视觉重量过于突兀。

## 02-grid —— 改后更好

改动后将原本悬浮在数据表格底部的行选统计信息（行数与选中项）规范整合到了最底部的全局状态栏左侧，消除了对网格底部的视觉干扰，层级更清晰统一；顶栏移除了生硬的竖线分割并微调了刷新/查询按钮间距，整体更简洁现代。

**新引入的问题**:无

## 03-nosql —— 改后更好

改动后将顶栏原本紧贴产品名 SelaDB 的「刷新」与「查询」按钮右移，精确对齐右侧主工作区边缘，明确了操作归属于当前活动数据源而非全局；底栏从仅截断在右侧区域改为通栏状态栏，消除了左侧导航树直冲窗口底部的断层感，窗口框架结构更规整稳定。

**新引入的问题**:连接状态详情（如 Redis 地址、编码及事务状态）被挪到了最左下角，位于包含 PostgreSQL、MySQL 等多数据源的侧边栏正下方，容易让用户产生该连接状态是全局状态而非当前工作区状态的从属认知混淆。

## 04-workbench-dark —— 改后更好

改动前「刷新」与「查询」紧贴 SelaDB Logo 挤在左侧侧边栏上方，并通过一条生硬的竖线分隔；改动后去除了该竖线，将「刷新」和「查询」右移至主工作区顶部对齐，使侧边栏品牌区与主区域操作按钮的归属与层次更分明。

**新引入的问题**:无明显视觉回退或排版缺陷。
